### Warehouse pricing privacy

- Backend: `StockItemWarehouseView` is an allow-list containing operational fields only.
  Tests assert (a) every warehouse field is cleared for `warehouse` by the classification map
  and (b) the raw HTTP body contains no `unitCost`, `lastPurchasePrice`, `standardSalesPrice`
  or `supplierName`. Live check of the running API: payload keys are `id, sku, name, unit,
  warehouseCode, lotNo, manufacturedOn, expiresOn, onHand, reserved, reorderPoint, available`.
- Frontend: warehouse types have no pricing fields; the dashboard loads stock from the
  warehouse API contract (offline fallback has the same shape); a test asserts no currency
  text renders anywhere in the warehouse workspace.

## Known limitations

- No authentication yet; `/login` validates input but does not sign in. Workspaces are
  reachable directly by URL with demo data — this is navigation, not security.
- No database connection; Prisma client is not generated; no migrations.
- Workspace module pages beyond each overview are descriptive placeholders.
- Contact form validates client-side only and sends nothing.
- Thai only; the `TH` language control is a non-interactive indicator.
- Workspaces use the dark theme only.
- Plan structure is a labelled sample; no commercial pricing exists.
- Barcode scanning is represented by disabled controls.
- Prisma 7 is used (8.x is still RC at time of writing); ESLint `jsx-a11y` is not installed
  because it does not yet support ESLint 10 — accessibility is covered by role-based tests
  and manual QA.
- Automated reduced-motion emulation was not run in the browser pane; behaviour is enforced
  by `MotionConfig reducedMotion="user"`, a global CSS media rule and explicit checks in the
  hero, buttons and counters.

## Recommended EP01 scope

1. **Database & identity:** PostgreSQL, Prisma client + migrations, seed for one demo company.
2. **Authentication:** email/password with Argon2id, HttpOnly Secure SameSite session cookies,
   CSRF protection, login rate limits, logout, session expiry.
3. **Authorization:** RBAC via Membership/Role/Permission; workspace derived from the session;
   a `requirePermission` pre-handler; object-level checks; deny-by-default tests.
4. **Audit persistence:** write `AuditLog` for every mutation via a single service.
5. **First real vertical slice:** Purchase Request end to end (create → submit → approve/reject
   → convert) on the existing state machine, with Warehouse/Operations as requesters and
   Purchasing as approver, including the audit trail and notifications stub.
6. **Frontend:** real login → land in primary workspace; route guard UX driven by
   `GET /api/v1/me`; PR screens in Purchasing and Warehouse.

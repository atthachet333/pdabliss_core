## 1. ภาพรวมสั้น ๆ

PDA BLISS CORE คือ **แพลตฟอร์มงานปฏิบัติการแบบแยกแผนก (Department-First)** สำหรับธุรกิจขนาดกลาง

- หนึ่ง workspace = หนึ่งบริษัท มีได้หลายสาขา
- พนักงานปฏิบัติการอยู่ **แผนกเดียว** และเห็นเฉพาะงานของแผนกตัวเอง
- ผู้บริหาร (Executive) **ดูได้ทุกแผนกแต่แก้ไขอะไรไม่ได้**
- คลังสินค้า **ไม่เห็นราคา ต้นทุน ยอดเงิน ลูกค้า หรือผู้ขาย**
- บัญชีใน CORE เป็นเพียงข้อมูลเชิงปฏิบัติการ (ตอนนี้มีเฉพาะ **มัดจำผู้ขาย**) — บัญชีแยกประเภทเป็นหน้าที่ของ PDA ONE ในอนาคต

สิ่งที่ยังไม่มี (เพื่อไม่ให้คาดหวังผิด): แดชบอร์ด KPI, ใบเสนอราคา/โปรโมชั่น, RFQ/พอร์ทัลผู้ขาย,
สแกนบาร์โค้ด/ซีเรียล, การแจ้งเตือน (อีเมล/ในแอป/LINE), ใบแจ้งหนี้/ลูกหนี้/เจ้าหนี้, การผลิตโดยไม่มีสูตร (BOM)
รายละเอียดทั้งหมดอยู่ใน [EP42_1_PRODUCT_GAP_MATRIX.md](EP42_1_PRODUCT_GAP_MATRIX.md)

## 2. เปิดระบบบนเครื่อง (Local)

ต้องมี PostgreSQL 18 ทำงานที่พอร์ต 5432 (เครื่องนี้เป็น Windows service `postgresql-x64-18`)
และไฟล์ `backend/.env` ที่มี `NODE_ENV=development` และ `ENABLE_DEMO_ROUTES=true` (มีอยู่แล้ว)

### 2.1 (แนะนำ) สำรองฐานข้อมูลก่อนเริ่ม UAT

การทดสอบจะสร้างและเปลี่ยนเอกสารจริงในฐานข้อมูล `pdabliss_core_dev` ถ้าต้องการย้อนกลับได้ ให้สำรองก่อน
(คำสั่งจะถามรหัสผ่านของผู้ใช้ `postgres` — ดูได้ใน `DATABASE_URL` ของ `backend/.env` อย่าพิมพ์ลงในรายงาน)

```bash
"/c/Program Files/PostgreSQL/18/bin/pg_dump.exe" -h localhost -U postgres -Fc -f "C:/Users/User/pdabliss_backups/before-EP42_2.dump" pdabliss_core_dev
```

EP42.1 สำรองไว้แล้วหนึ่งชุด: `C:/Users/User/pdabliss_backups/pdabliss_core_dev-before-EP42_1-20261110-092407.dump`
(ตรวจแล้วว่ากู้คืนได้ครบทุกแถว)

### 2.2 เปิด backend (พอร์ต 1112)

เปิด Terminal ที่ 1:

```bash
npm --prefix backend run dev
```

รอจนเห็นข้อความ `Server listening at http://127.0.0.1:1112`
ตรวจสุขภาพระบบได้ที่ <http://localhost:1112/health> (ต้องเห็น `"status":"ok"`)

### 2.3 เปิด frontend (พอร์ต 1111)

เปิด Terminal ที่ 2:

```bash
npm --prefix frontend run dev
```

### 2.4 ตรวจข้อมูลสาธิต (ไม่บังคับ)

```bash
npm --prefix backend run db:seed:demo
```

คำสั่งนี้ **เพิ่มเฉพาะสิ่งที่ขาด** และไม่แก้เอกสารที่มีอยู่ ถ้าข้อมูลครบแล้วจะแสดง `unchanged` ทุกบรรทัด
(EP42.1 ทดสอบกับสำเนาของฐานข้อมูลนี้แล้ว: ไม่มีแถวใดเปลี่ยน)

### 2.5 เข้าเว็บ

เปิด <http://localhost:1111/login>

## 3. การเข้าสู่ระบบด้วยบัญชีสาธิต

- ในโหมด development หน้าเข้าสู่ระบบมี **รายการบัญชีสาธิต** — เลือกบัญชีแล้วระบบจะใส่อีเมลให้
- รหัสผ่านของแต่ละบัญชีอยู่ในไฟล์ `backend/.env` ของเครื่องคุณ (ตัวแปร `DEMO_*_PASSWORD` ตามตารางข้อ 4)
  **เอกสารนี้ไม่ใส่รหัสผ่านจริง** และห้ามคัดลอกรหัสผ่านลงในรายงานปัญหา
- บัญชีสาธิตทั้ง 9 **ไม่ต้องใช้รหัส OTP ทางอีเมล** (เฉพาะ development; ระบบ production ปฏิเสธเสมอ)
- ภาษา: ปุ่ม TH / EN / 中文 ที่ส่วนหัว CORE จำภาษาไว้ทุกหน้า

**เคล็ดลับลดการสลับบัญชี:** หนึ่งหน้าต่างเบราว์เซอร์ = หนึ่งคน
ใช้ **หน้าต่างปกติสำหรับ `owner.demo`** และ **หน้าต่าง Private/Incognito สำหรับพนักงานที่กำลังทดสอบ**
(ปิดหน้าต่าง Private แล้วเปิดใหม่เมื่อต้องการเปลี่ยนเป็นพนักงานคนถัดไป หรือกด **ออกจากระบบ** มุมขวาบน)

**สาขาที่ทำงาน:** บัญชีที่มีสองสาขาจะเห็นหน้า **เลือกสาขาที่จะทำงาน** ก่อน — เลือกสาขาตามตาราง แล้วกด **เข้าสู่ CORE**
เปลี่ยนภายหลังได้ที่เมนูซ้าย **เปลี่ยนสาขา** (ระบบพากลับมาหน้าเดิม) สาขาปัจจุบันแสดงที่ส่วนหัวเสมอ
ถ้ายังไม่เลือกสาขา ระบบให้ **ดู** ได้เฉพาะสาขาของตนเอง แต่จะ **ไม่ให้สร้างเอกสาร** (ป้องกันการลงเอกสารผิดสาขา)

**เมนู:** จอกว้าง 1280px ขึ้นไปเป็นแถบเมนูด้านซ้าย จอเล็กกว่านั้นกดปุ่ม **เมนู** มุมขวาบน

## 6. ทดลองใช้ทีละบัญชี

**หน้าปฏิเสธสิทธิ์ที่ควรเห็น** (ตรวจในเบราว์เซอร์จริง EP42.1): หัวข้อ **"ไม่มีสิทธิ์เข้าถึงหน้านี้"** ข้อความ "คุณไม่มีสิทธิ์ทำรายการนี้"
และปุ่ม **ย้อนกลับ** / **ไปที่หน้าแรก CORE** — ทุกที่ที่คู่มือเขียนว่า "ไม่มีสิทธิ์" หมายถึงหน้านี้

แต่ละหัวข้อบอก: สาขา → เมนู → เอกสารที่ให้เปิด → สิ่งที่ให้ลองทำ → ผลที่ควรเห็น → สิ่งที่ **ต้องถูกปฏิเสธ** → ใครทำขั้นต่อไป
(ลำดับการทดสอบที่ประหยัดการสลับบัญชีที่สุดอยู่ใน [เช็กลิสต์](EP42_1_UAT_CHECKLIST.md))

### 6.1 `executive.demo` — ผู้บริหาร (อ่านอย่างเดียว)
- สาขา `00001` → **เข้าสู่ CORE**
- เปิด **คำสั่งขาย** → SO-202611-000011 (ส่งถึงแล้ว) · **การผลิต** → MO-202611-000009 · **สต็อกคงคลัง** · **ใบสั่งซื้อ** · **มัดจำผู้ขาย**
- ผลที่ควรเห็น: เห็นข้อมูลทุกแผนกรวมราคา/ยอดเงิน แต่ **ไม่มีปุ่มสร้าง อนุมัติ ยืนยัน หรือบันทึก** ที่ใดเลย
- ต้องถูกปฏิเสธ: พิมพ์ URL `/core/sales/orders/new` → ไม่มีแบบฟอร์มสร้าง เห็นหน้า **"ไม่พบหน้านี้"** ("ไม่พบคำสั่งขายนี้ หรือคุณไม่มีสิทธิ์ดู")
  และเซิร์ฟเวอร์ปฏิเสธการสร้างทุกชนิด (403) ; ไม่มีเมนูตั้งค่าบริษัท
- ข้อจำกัดที่รู้แล้ว: ยังไม่มี "Executive Command Center" (สรุป KPI ข้ามแผนก) — หน้า CORE เป็นการ์ดลิงก์ไปแต่ละแผนก

### 6.2 `admin.demo` — ผู้ดูแลระบบของบริษัท
- ไม่ต้องเลือกสาขา → Company Control Center
- เปิด **ผู้ใช้** → Demo Staff → สิทธิ์: เห็นข้อยกเว้น DENY `warehouse.receiving.process` · **ข้อมูลหลัก** (ลูกค้า/ผู้ขาย/สินค้า) · **สาขา**
- ต้องถูกปฏิเสธ: เข้า CORE แล้วเห็นข้อความ "ยังไม่มีแผนกที่มอบหมายให้คุณ" ; URL `/core/sales` → ไม่มีสิทธิ์ ;
  **ตั้งค่า → การอนุมัติเอกสาร** เปลี่ยนไม่ได้ ("เฉพาะเจ้าของบริษัทเปลี่ยนการตั้งค่านี้ได้")
- หมายเหตุ: ผู้ดูแลระบบจัดการระบบได้ แต่ **ไม่ได้รับสิทธิ์งานปฏิบัติการ** โดยอัตโนมัติ

### 6.3 `accounting.demo` — บัญชี (สาขา `00000`)
- เข้า CORE ทันที → **มัดจำผู้ขาย** → PO-202611-000002 (มัดจำ 30 %)
- ลองทำ: ยืนยันมัดจำ โดยใส่เลขอ้างอิงการโอน (เช่น `UAT-TRF-001`) หรือยกเว้นมัดจำ (ต้องใส่เหตุผล)
- ผลที่ควรเห็น: ใบสั่งซื้อเปลี่ยนเป็น **รอรับสินค้า**
- ต้องถูกปฏิเสธ: URL `/core/warehouse/inventory`, `/core/production` → ไม่มีสิทธิ์

- ข้อจำกัด: CORE มีเฉพาะมัดจำผู้ขาย ไม่มีใบแจ้งหนี้ ลูกหนี้ เจ้าหนี้ หรือสมุดบัญชี (เป็นงานของ PDA ONE)

### 6.4 `warehouse.demo` — คลังสินค้า (สาขา `00001`)
- **รับสินค้า:** ภาพรวมคลังสินค้า → แท็บ **รอรับสินค้า** → PO-202611-000007 → รับ 6 L เข้า MAIN ใส่เลขล็อต (เช่น `UAT-UVF-1`) และวันหมดอายุ → **บันทึกรับสินค้า**
  - ผล: ใบสั่งซื้อเป็น **รับครบ**, สต็อก RM-000003 เพิ่ม 6 L และการขาดวัตถุดิบของ MO-202611-000010 พร้อมให้ปฏิบัติการจอง
- **หยิบ–แพ็ก–เตรียมส่ง:** **รอหยิบสินค้า** → SO-202611-000003 → สร้างใบหยิบ → เริ่ม → ยืนยันจำนวน → สร้างแพ็ก → ยืนยัน → เตรียมการจัดส่ง
  - ผล: การจัดส่งพร้อม; **ไม่มีปุ่ม "ส่งออก (Dispatch)"** — เป็นขั้นของผู้จัดการ (`owner.demo`)
- **สต็อก:** สต็อกคงคลัง → ดูล็อตและวันหมดอายุ (FG-DEMO-B ใกล้หมดอายุ) ; แท็บ **ความเคลื่อนไหว** เห็นทุกการเคลื่อนไหวพร้อมเลขเอกสาร
- **รับสินค้าสำเร็จรูป:** MO-202611-000006 มี 2 ชิ้นรอรับ → สร้างฉบับร่าง ; ปุ่ม **ผ่านรายการรับเข้าคลัง** เป็นของ `owner.demo`
- ความเป็นส่วนตัว: **ไม่มีหน้าจอใดแสดงราคา ต้นทุน ยอดเงิน ลูกค้า หรือผู้ขาย** — ถ้าเห็น ให้รายงานเป็นปัญหาร้ายแรง
- ต้องถูกปฏิเสธ: URL `/core/sales`, `/core/purchasing/orders`, `/core/accounting/deposits` → ไม่มีสิทธิ์

### 6.6 `operations.demo` — ปฏิบัติการ/การผลิต (สาขา `00001`)

  - ฐานข้อมูลนี้ (อนุมัติตนเองได้): `operations.demo` ทำได้ครบทุกขั้น
  - ถ้าเปิด "ต้องอนุมัติโดยผู้อื่น": **อนุมัติ / ผ่านรายการเบิก / รับผลผลิต** ของเอกสารที่ตนเองสร้างจะถูกปฏิเสธ → ให้ `owner.demo` ทำ

## 7. ทดสอบนโยบายการอนุมัติ (EP41) อย่างปลอดภัย

ทำโดย `owner.demo` เท่านั้น และ **เปลี่ยนกลับเมื่อทดสอบเสร็จ** (ทั้งสองครั้งถูกบันทึกในกิจกรรม)

1. Company Control Center → **ตั้งค่า** → **การอนุมัติเอกสาร** → เลือก **ต้องอนุมัติโดยผู้อื่น** → บันทึก
2. `operations.demo` สร้างใบสั่งผลิต → ส่ง → กด **อนุมัติ** เอง → **ถูกปฏิเสธ** ("ต้องให้ผู้อื่นที่มีสิทธิ์อนุมัติ")
3. `owner.demo` อนุมัติใบนั้นได้ทันที (ไม่ใช่ผู้สร้าง จึง **ไม่ต้องยกเว้น**)
4. `owner.demo` สร้างใบปรับยอดสต็อกเอง → ส่ง → อนุมัติ → หน้าต่าง **ยกเว้นโดยเจ้าของบริษัท** เปิดขึ้น
   - เหตุผลสั้นกว่า 10 ตัวอักษร ปุ่มยืนยันกดไม่ได้ ; **ยกเลิก** หรือ Esc = ไม่มีอะไรเปลี่ยน
   - ใส่เหตุผล ≥ 10 ตัวอักษร → **อนุมัติด้วยการยกเว้นของเจ้าของ** → สำเร็จ
5. ความปลอดภัย → กิจกรรม: เห็น "เจ้าของบริษัทยกเว้นการอนุมัติโดยผู้อื่น" พร้อมเลขเอกสาร สาขา และเหตุผล และเห็นการเปลี่ยนนโยบาย
6. **เปลี่ยนกลับ** เป็น "อนุญาตให้อนุมัติเอกสารของตนเอง (ตามสิทธิ์)"

`admin.demo` และ `executive.demo` เปลี่ยนนโยบายไม่ได้ (ตรวจแล้วใน EP42.1)

## 8. ลำดับงานข้ามแผนก (ใครทำต่อจากใคร)

| สายงาน | ลำดับ (บัญชี) |
| --- | --- |
| จัดซื้อ → คลัง | สร้าง/ส่ง PR (operations) → อนุมัติ (purchasing) → สร้างและออก PO (purchasing) → รับบางส่วน + รับครบ (warehouse) → เห็นล็อตในสต็อก |
| ขาย → จัดส่ง | ร่าง/ส่ง (sales) → ยืนยัน + จอง FEFO (owner) → หยิบ/แพ็ก/เตรียมส่ง (warehouse) → ส่งออก + ส่งถึง (owner) → sales เห็น "ส่งถึงแล้ว" |
| ขาดของ → ผลิต → ขาย | SO-202611-000014 ไม่มีสต็อก → MO-202611-000010 รอ RM-000003 (purchasing เห็นในรายการขาด) → warehouse รับ PO-202611-000007 → operations จอง/ผลิต/ยอมรับ → warehouse ร่างรับสินค้าสำเร็จรูป → owner ลงรับ → operations ปิดงาน → owner จองให้ SO-202611-000014 → warehouse หยิบ/แพ็ก → owner ส่งออก/ส่งถึง |
| มัดจำ | purchasing ออก PO แบบมีมัดจำ → accounting ยืนยัน/ยกเว้น → PO เป็นรอรับสินค้า |

EP42.1 ซ้อมสายงานทั้งหมดนี้ด้วย API จริงบน **สำเนา** ของฐานข้อมูลนี้ (58/58 ผ่าน) และบนฐานข้อมูลใหม่ (120 + 203 ผ่าน)
แต่ **ยังไม่ใช่การยอมรับโดยผู้ใช้** — นั่นคือหน้าที่ของ EP42.2

## 9. วิธีรายงานปัญหา

จดลงช่อง "หมายเหตุ/หลักฐาน" ในเช็กลิสต์ หรือเปิดเป็นรายการแยก ใช้รูปแบบนี้:

```
รหัสเคส: (เช่น UAT-B-04)
บัญชี + สาขา + ภาษา + ความกว้างจอ: (เช่น sales.demo · 00001 · TH · 1280px)
URL:
ขั้นตอนที่ทำ: 1) … 2) … 3) …
ผลที่คาดหวัง:
ผลที่เกิดจริง: (ข้อความบนจอตามตัวอักษร)
ความรุนแรง: P0 ข้อมูลผิด/รั่ว · P1 ทำงานต่อไม่ได้ · P2 ทำได้แต่ยาก/สับสน · P3 ความสวยงาม/ถ้อยคำ
ภาพหน้าจอ: (ถ้ามี — ปิดรหัสผ่าน/คุกกี้ก่อน)
```

**ห้าม** ใส่รหัสผ่าน คุกกี้ หรือเนื้อหาไฟล์ `.env` ในรายงาน
ถ้าเห็นราคา/ยอดเงินบนหน้าจอคลังสินค้า หรือเห็นเอกสารของสาขาที่ไม่มีสิทธิ์ ให้จัดเป็น **P0** ทันที

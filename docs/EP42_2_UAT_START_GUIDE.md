## 1. UAT Sandbox คืออะไร และต่างจาก dev อย่างไร

| | ระบบพัฒนา (dev) | **UAT Sandbox** |
| --- | --- | --- |
| เว็บ | `http://localhost:1111` | **`http://127.0.0.1:1211`** |
| API | `http://localhost:1112` | **`http://127.0.0.1:1212`** |
| ฐานข้อมูล | `pdabliss_core_dev` | **`pdabliss_core_uat`** |
| นโยบายอนุมัติเริ่มต้น | อนุมัติเอกสารของตนเองได้ | **ต้องอนุมัติโดยผู้อื่น** (ค่าเริ่มต้นของบริษัทใหม่) |
| เริ่ม/หยุด | `npm run dev` | **`uat\uat.cmd start` / `uat\uat.cmd stop`** |
| ย้อนกลับเป็นข้อมูลตั้งต้น | ไม่มี | **`uat\uat.cmd reset`** (สำรองข้อมูลเดิมให้ก่อนเสมอ) |

**ทำไมต้องเป็น `127.0.0.1` ไม่ใช่ `localhost`:** เบราว์เซอร์แยกคุกกี้ตามชื่อโฮสต์ (ไม่แยกตามพอร์ต)
การใช้ `127.0.0.1` ทำให้การเข้าสู่ระบบของ UAT **ไม่ชนกับ** การเข้าสู่ระบบของ dev ที่ `localhost` แม้เปิดพร้อมกันในเบราว์เซอร์เดียว
ถ้าเปิด `localhost:1211` จะเข้าสู่ระบบไม่ได้ — ให้ใช้ `127.0.0.1:1211` เท่านั้น

ข้อมูลทำงานของ sandbox (ไฟล์ข้อมูลตั้งต้น สำรอง log) อยู่นอกโปรเจกต์ที่ `C:\Users\User\pdabliss_uat\`
(เปลี่ยนได้ด้วยตัวแปร `UAT_HOME`) — ไม่เข้า git และไม่อยู่ในโฟลเดอร์ OneDrive ของโปรเจกต์

## 2. เปิด UAT (ทุกครั้งที่จะทดสอบ)

เปิด Terminal (PowerShell, Command Prompt หรือ Git Bash) ที่โฟลเดอร์โปรเจกต์ `pdabliss_core` แล้วพิมพ์:

```bash
uat\uat.cmd start --open
```

(ใน Git Bash ใช้ `node uat/uat.mjs start --open` แทนได้ — ทุกคำสั่งในคู่มือนี้ใช้รูปแบบ `node uat/uat.mjs …` ได้เหมือนกัน)

ผลที่ควรเห็น (ประมาณ 10–20 วินาที):

```
  OK    pdabliss_core_uat is on the committed migrations
  OK    backend http://127.0.0.1:1212 — ok, environment development
  OK    frontend http://127.0.0.1:1211/login
  OK    demo persona list: 9 accounts
UAT is ready: http://127.0.0.1:1211/login   (use 127.0.0.1, not localhost)
```

`--open` จะเปิดหน้าเข้าสู่ระบบให้อัตโนมัติ ถ้าไม่ใช้ ให้เปิด <http://127.0.0.1:1211/login> เอง

สิ่งที่ `start` ตรวจก่อนเปิดเสมอ: ฐานข้อมูล UAT มีอยู่และอยู่บน migration ล่าสุด, พอร์ต 1211/1212 ว่าง,
ยังไม่มี UAT ตัวอื่นทำงานอยู่ — ถ้าไม่ผ่านจะ **ไม่เปิดอะไรเลย** และบอกเหตุผล

**ระบบ dev (1111/1112) ไม่ถูกแตะต้อง** — เปิดค้างไว้พร้อมกันได้

## 3. ตรวจสถานะ

```bash
uat\uat.cmd status
```

ต้องเห็นทั้งหมดเป็น OK และบรรทัดสำคัญ:
`UAT backend is connected to database "pdabliss_core_uat"` — ยืนยันว่า API ของ UAT ใช้ฐานข้อมูล UAT จริง
(บรรทัดนี้จะปรากฏหลังมีการใช้งานครั้งแรก เช่น หลังเข้าสู่ระบบ)

ตรวจบัญชีสาธิตทั้ง 9 แบบเข้าสู่ระบบจริงผ่าน API (ไม่บังคับ):

```bash
uat\uat.cmd verify --api
```

ต้องจบด้วย `VERIFY: PASS` (คำสั่งนี้สร้างประวัติการเข้าสู่ระบบในฐานข้อมูล UAT — ไม่กระทบเอกสาร)

## 4. ปิด UAT

```bash
uat\uat.cmd stop
```

หยุด **เฉพาะ** โปรเซสที่ `start` เปิดไว้ (ตรวจจากเครื่องหมายเฉพาะของ UAT ก่อนหยุดทุกครั้ง) — ไม่ปิดระบบ dev หรือโปรแกรมอื่น
ข้อมูลที่ทดสอบไว้ **ยังอยู่ครบ** — เปิดใหม่ด้วย `start` แล้วทำต่อได้

## 5. เมื่อมีปัญหาการเปิดระบบ

```bash
uat\uat.cmd doctor
```

แสดง: เวอร์ชัน Node, PostgreSQL ที่เชื่อมต่อ, ชื่อฐานข้อมูล dev (เพื่อยืนยันว่า UAT ไม่ใช่ dev), พอร์ต 1211/1212/1111/1112 ว่างหรือไม่ (และโปรแกรมที่ใช้อยู่ถ้าระบบอนุญาตให้ดู), ไฟล์ข้อมูลตั้งต้นตรง checksum หรือไม่

| อาการ | วิธีแก้ |
| --- | --- |
| `port 1211 is in use by another program` | ปิดโปรแกรมนั้น หรือดู `doctor` ว่าเป็นใคร — เครื่องมือ UAT จะไม่ปิดโปรแกรมอื่นให้ |
| `the UAT backend is already running` | UAT เปิดอยู่แล้ว ใช้ `status` หรือ `stop` แล้ว `start` ใหม่ |
| เข้าสู่ระบบไม่ได้ / ถูกพากลับหน้าเข้าสู่ระบบ | ตรวจว่าใช้ `127.0.0.1:1211` ไม่ใช่ `localhost:1211` |
| `is not on the committed migrations` | โค้ดใหม่กว่าฐานข้อมูล — แจ้งทีมพัฒนา (อย่า migrate เอง) |
| ต้องการดู log | `C:\Users\User\pdabliss_uat\logs\backend.log` และ `frontend.log` |

## 6. การเข้าสู่ระบบด้วยบัญชีสาธิต

1. เปิด <http://127.0.0.1:1211/login>
2. ใต้ฟอร์มมีกล่อง **Demo accounts (development only)** — กดชื่อบัญชี ระบบเติมอีเมลให้
3. ใส่รหัสผ่านของบัญชีนั้นจากไฟล์ `backend/.env` ในเครื่อง (ตัวแปร `DEMO_*_PASSWORD` ตามตารางข้อ 7) → **เข้าสู่ระบบ**
   - **ไม่ต้องใช้รหัส OTP** ทางอีเมล (เฉพาะบัญชีสาธิตในโหมด development)
   - **ห้ามใส่รหัสผ่านจริงลงในรายงานปัญหา**
4. บัญชีที่มีสองสาขา: หน้า **เลือกสาขาที่จะทำงาน** → เลือกสาขาตามตาราง → **เข้าสู่ CORE**

**สองหน้าต่าง ลดการสลับบัญชี:** หน้าต่างปกติ = `owner.demo` (เปิดค้างไว้) · หน้าต่าง Private/Incognito = พนักงานที่กำลังทดสอบ
(สลับพนักงาน: กด **ออกจากระบบ** มุมขวาบน หรือปิดหน้าต่าง Private แล้วเปิดใหม่)

ตรวจแล้วใน EP42.2: เข้าสู่ระบบผ่านฟอร์มจริงที่ `127.0.0.1:1211` → เลือกสาขา → CORE → รายการคำสั่งขาย 14 รายการ แสดงถูกต้อง

## 9. สำรอง และย้อนกลับเป็นข้อมูลตั้งต้น (เมื่อจำเป็นเท่านั้น)

ไม่มีการ reset อัตโนมัติ — ข้อมูลที่คุณทดสอบจะอยู่จนกว่าคุณสั่งเอง

### 9.1 สำรองระหว่างทดสอบ (แนะนำก่อนเริ่มแต่ละวัน)

```bash
uat\uat.cmd backup --label day1
```

ได้ไฟล์ใน `C:\Users\User\pdabliss_uat\backups\` ซึ่งถูกตรวจว่าอ่านกลับได้แล้ว

### 9.2 ย้อนกลับเป็นข้อมูลตั้งต้น

1. `uat\uat.cmd stop` (reset จะ **ปฏิเสธ** ถ้า UAT ยังทำงาน)
2. `uat\uat.cmd reset --confirm pdabliss_core_uat`
3. ระบบถามให้พิมพ์ชื่อฐานข้อมูลอีกครั้ง → พิมพ์ `pdabliss_core_uat` → Enter
4. สิ่งที่ระบบทำตามลำดับ:
   - ตรวจว่าเป้าหมายคือฐานข้อมูล UAT บนเครื่องนี้ (ปฏิเสธ dev, production หรือชื่ออื่นทุกกรณี)
   - ตรวจ checksum ของไฟล์ข้อมูลตั้งต้น
   - **สำรองข้อมูลปัจจุบันก่อน** เป็น `…backups\pdabliss_core_uat-before-reset-<เวลา>.dump` (หลักฐาน UAT ไม่หาย)
   - แทนที่ด้วยข้อมูลตั้งต้น แล้วตรวจว่าตรงกับข้อมูลตั้งต้นทุกตาราง และบัญชีสต็อกกระทบยอดเป็นศูนย์
5. `uat\uat.cmd start`

### 9.3 นำข้อมูลที่สำรองไว้กลับมา (เช่น ต้องการดูหลักฐานเก่า)

```bash
uat\uat.cmd stop
uat\uat.cmd restore --from "C:\Users\User\pdabliss_uat\backups\<ชื่อไฟล์>.dump" --confirm pdabliss_core_uat
```

ข้อมูลปัจจุบันจะถูกสำรองก่อนเช่นกัน

### สิ่งที่เครื่องมือ **ไม่ยอมทำ** (ตรวจแล้ว)
- แตะ `pdabliss_core_dev` หรือฐานข้อมูลชื่ออื่นที่ไม่ใช่ `pdabliss_core_uat` / `pdabliss_core_uat_<ชื่อ>`
- ทำงานเมื่อ `NODE_ENV=production` หรือฐานข้อมูลไม่ได้อยู่บนเครื่องนี้
- reset/restore โดยไม่มี `--confirm <ชื่อฐานข้อมูล>` ที่ตรงกัน หรือขณะ UAT ทำงาน
- ปิดโปรแกรมที่ไม่ได้เปิดโดย `start`

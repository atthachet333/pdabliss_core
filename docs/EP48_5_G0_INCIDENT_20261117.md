## 3. Corrective amendment (this commit)

### Monitoring — `ops/ep48_5/g0-supervisor.mjs` replaces `g0-monitor.ps1` (deleted)

- Every decision is a pure, typed Node function, unit-tested and mutation-checked. Windows facts come from `g0-harness/g0-facts.ps1`, which is read-only and makes one PowerShell call per round.
- **Names.** The temporary port is `tempPgPort` / `$TempPgPort` and production ports are `appPort`. No PowerShell script may spell one variable two ways, or reuse a script parameter as a loop or assignment target. This is checked in Node (preflight C10, R1) and with the PowerShell AST on the host (preflight W1, Test-G0Harness P2).
- **Baseline typing.** The baseline is a typed **array** `{ appPort:int, host, status:int, statuses:int[], medianMs:int, limitMs:int }`; nothing is looked up through a dictionary. Legacy object-form baselines are normalised (R2).
- **Fail closed.** The monitor refuses to start (it writes STOP and exits with code 2) if any of these is true:
  - no PM2 tree or postmaster;
  - no production ports;
  - an unstable or invalid status;
  - a missing latency sample or limit;
  - no loopback probe address.

  The runner refuses unless `baseline.json` has `valid: true` (R3, R10c, M14, M15).
- **HTTP status.** A status is compared with the port's own baseline status, so 200 = 200 and 404 = 404 are healthy, while 500 or no answer is a finding (R4, R5).
- **Latency.** The limit is max(⌈1.5 × median⌉, median + 50 ms); a probe above the limit for 2 consecutive rounds is a finding, and a healthy round resets the count (R6).
- **Temporary PostgreSQL.** Only listeners on 55443 are checked: anything other than 127.0.0.1, or an owner that is not a G0 process, is a finding. A G0 process on a non-loopback address (IPv4 or IPv6) is a finding; `::1` is loopback. A G0 connection to 5432 is a finding (R7, R7b).
- **No alert flood.** Each condition is logged once. Repeats are counted (`repeatsSuppressed`). If the runner doesn't acknowledge STOP within 300 s, one notice is logged (R10b).
- **Lifecycle.** The monitor ends on `MONITOR-END`, when the runner process ends (two independent checks: liveness, and PID plus start time in the facts) or after 8 hours, and it always writes `monitor-final.json` with the I5 comparison (R10, R10d). A monitor crash writes STOP.

### Runner lifecycle — `Run-G0.ps1` v3 and `g0-common.ps1`

- **One way to run a program.** Every external program goes through `Invoke-G0Bounded`:
  - `Start-Process` writes stdout and stderr to **files**, so there is no pipe and a grandchild cannot hold the runner (R8, Test-G0Harness P3);
  - a 500 ms polling loop returns on exit, on STOP, on monitor loss (fail closed) or at a per-phase deadline (R9, P4).
- **Stopping a step.** On STOP, monitor loss or a timeout, the step's **own** tree is stopped by `g0-supervisor.mjs stop-tree`:
  - every PID is re-verified by its start time;
  - production processes (PM2 daemons and descendants, the postmaster and its `pg_ctl`, MariaDB, cloudflared), anything older than the runner, Windows system processes and PostgreSQL are refused;
  - there is no `taskkill /T`, no `Stop-Process` and no stopping by image name (R9b, R12).
- **Shutdown** (`Complete-G0`, bounded; the report is always written in a `finally` block):
  1. Verify the temporary instance's identity: the PID in `postmaster.pid`, its data folder, `-p 55443`, 127.0.0.1 only, and that it is not production.
  2. Stop it with `pg_ctl stop -m fast -w -t 90`.
  3. Verify it has stopped. If it hasn't, it is left running for an owner decision and never killed (R11).
  4. Write `MONITOR-END`; if the monitor hasn't ended within 90 s, stop it as a verified tree.
  5. Run the collector "after", bounded.
  6. Copy the logs; nothing is deleted.
- **Static rules** (preflight C2) forbid in the runner:
  - `*>` and `2>&1` redirection, and the retired `Native` helper;
  - calling PostgreSQL programs directly (`$PgBin` outside `Invoke-G0Phase`);
  - `Start-Job`, `taskkill`, `Stop-Process` and `.Kill(`;
  - `Start-Process` except to start the monitor;
  - supervisor test hooks;
  - setting `DATABASE_URL` / `PG*` / `NODE_OPTIONS`, any 5432 reference and any delete;

  and they require the preflight first, the monitor before the first step, a refusal on an invalid baseline, pg_ctl start through the helper, and a verified graceful stop.

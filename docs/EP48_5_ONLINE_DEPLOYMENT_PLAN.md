### 0.2 Architecture changes from O0

- **Ingress (dedicated tunnel `pdabliss-core`):** rules are evaluated in order:
  1. `^/api/v1/auth/(register|verification/resend)` → `http_status:404`;
  2. `^/register` → `http_status:404`;
  3. `^/api/` → `http://127.0.0.1:1312`;
  4. everything else → `http://127.0.0.1:1311`.

  `/health` is **not** routed publicly; it is checked on loopback. If the dashboard does not offer `HTTP_STATUS`, rules 1–2 become one hostname-scoped WAF custom rule (block), with owner approval.
- **Access:**
  - application A1 is path-scoped, permanent until EP48.6: `core.pdabliss.com/platform*` and `core.pdabliss.com/api/v1/platform/*`, allowing named operators;
  - application A2 is the whole hostname, **mode R only**, for named testers.
- **Web serving:** the online profile uses a hardened static server (`ops/ep48_5`, O1), not Vite `preview()` (B3). That covers:
  - security headers;
  - `X-Robots-Tag: noindex` unless the owner decides otherwise (OD-P4);
  - the same fail-closed bind rules.
- **Mail:** Hostinger SMTP, `smtp.hostinger.com:587` STARTTLS (`SMTP_SECURE=false`, enforced by `requireTLS`), mailbox `notify@pdabliss.com` (create if absent). This is required because `pdabliss.com` has DMARC `p=reject` with strict alignment and Hostinger-only SPF / DKIM.
- **Connector:** `core-tunnel` WinSW service, `cloudflared tunnel --no-autoupdate --metrics 127.0.0.1:20243 run --token-file D:\pdabliss-core-staging\config\core-tunnel.token` (20243 free; `--token-file` already used on this host).

               │ ingress:  path ^/(api|health)(/|$)  → http://127.0.0.1:1312

### 5.2 Rollback (extends `EP48_5_ROLLBACK_PLAN.md`; nothing here touches production)

| Level                          | Action                                                                                                                                                                                                                                                                       | Effect                                                                                                    |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| **R0 — close the door** (seconds) | `Stop-Service core-tunnel`                                                                                                                                                                                                                                                   | `core.pdabliss.com` no longer reaches the host (Cloudflare error page, still behind Access); CORE keeps running on loopback |
| **R1 — stop CORE**             | `Stop-Service core-tunnel, core-staging-web, core-staging-api` (the database stays up)                                                                                                                                                                                       | CORE fully offline; reversible                                                                            |
| **R1b — remove the route**     | In the dashboard:<br>1. delete the `pdabliss-core` public hostname and its DNS record;<br>2. **restore the OO-1 record** if one existed;<br>3. keep the Access application until the hostname is gone, then remove it last. | the domain returns to its prior state                                                                     |
| **R2 — previous release**      | as the existing R2: point `current` at the previous `releases\<sha>`, start the services                                                                                                                                                                                      | code rollback (no migration change between releases in EP48.5)                                           |
| **R3 — database reset point**  | as the existing R3 (needs A-8b)                                                                                                                                                                                                                                              | demo data back to the O3 reset point                                                                      |
| **R4 — full removal**          | as the existing R4 (needs A-8b), plus:<br>• `core-tunnel` service unregistered;<br>• the tunnel `pdabliss-core` deleted;<br>• the token file emptied.                                                                                                                       | the host and Cloudflare return to their O0 state                                                          |

**Never in a rollback:**
- touching PM2;
- touching the shared PostgreSQL;
- touching MariaDB;
- touching the `Cloudflared` / `CloudflaredS2A` services or their ingress;
- touching other Access applications;
- touching zone-wide settings;
- killing processes by name.
